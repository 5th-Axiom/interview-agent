# 被打断后的重复提问修复

日期：2026-09-11。此次修改针对“问题部分播放 → 候选人提前回答 → 临时识别被最终文本轻微修订”的组合。基线为 `bfe3806`；不改数据库结构、供应商配置、共享服务进程或发布状态。

## 实现

- 对话投影保留所有已生成的提问及原始顺序，分别标记完整、部分或无播放确认。未完整播放的全文带明确说明，不能推断候选人听到哪些字；后续输入保留与此前提问的时间顺序关系，不由代码断言“已回答”。模型结合原文处理回答、澄清、等待、纠正和结束意图。
- 仅在同一 `input_turn_id` 的修订链内判断内容是否变化。最终文本、识别确定性和转写覆盖仍写入原始事件；可确认的格式变化不再取消和重新生成模型回复。不同发言即使文字相同，也不会被全局去重。
- 格式白名单只覆盖空白排版、句尾句号和句首语气词后的逗号；保留英文词边界、任意其他标点、问号、数字、小数、百分号和否定词。没有使用文本相似度阈值或回答长度阈值。
- 即使最终识别文字完全不变，仍补存 provisional → final 和实际音频覆盖，避免只取消重复生成却漏掉证据。新的对话投影版本为 `conversation-2026-09-v3`，生成事件记录该版本，便于追查。

## 本次验证

- `npm test` 本次运行 53 项通过，包括新增的 5 项回归测试；`npm run typecheck` 通过。
- 真实 Relay 子进程与协议替身覆盖：格式修订保存但不重启回复、重复 final 不重复落库、否定纠正仍重启、独立新发言即使同文仍回复；ASR 单独验证同文 final 补齐音频覆盖。
- 当前已配置的真实模型对 4 个合成文本场景进行回放：Agent Loop 回答后追问具体流程；没听清时澄清原问；要求等待时让出话权；否定缓存后承认直接读取数据库并转向对应细节。记录在 Git 忽略的 `.local/side-continuity-replay.json`。

这些结果证明确定性的触发与历史丢失问题已修复，并提供有限的真实模型样本；不等于完成真人麦克风、重复率或双人盲评验收。界面原始事件仍会保留临时文本和最终修订，不能把原始记录中的两条修订误读成模型收到了两次独立回答。现有共享 Relay 需由主会话后续重启或发布后加载新代码。
