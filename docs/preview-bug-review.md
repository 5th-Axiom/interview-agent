# 配置台试聊与关联流程排查

日期：2026-09-15。基线：`7a225bf`。

## 已复现并修复

| 问题 | 复现与原因 | 修复 |
| --- | --- | --- |
| 关闭试聊未真正结束会话 | 编辑 Prompt、开启试聊后按 Esc。原关闭请求未带 `expected_version`，接口返回 409，弹窗却已卸载，只剩无法直接重试的提示。 | 关闭操作复用语音会话的结束流程，使用当前版本、停止声音并补传；成功后才关闭。失败保留弹窗与重试入口。原生 Dialog 的 Esc 交由受控状态决定关闭，避免提前卸载。 |
| 试聊计时一直为 00:00 | 配置台只保留创建时的会话，`onRefresh` 为空，没有读取 `active_since` 和累计时长。 | 启动、控制操作及定时刷新会话；丢弃已关闭或较旧的刷新结果。语音 Hook 不再被旧版本快照覆盖。 |
| 新建岗位保存期间的后续输入丢失 | 用本地代理延迟保存 12 秒，提交第一版后继续输入第二版。新建路由跳转到岗位详情时重新初始化表单，把第二版替换成第一版。 | 跨路由传递当前草稿、已保存基线和修订号；后续输入保留为“有未保存修改”。“保存后离开”期间又有编辑时保留页面。 |
| 麦克风权限错误缺少可操作提示 | 真实模式在系统拒绝麦克风时直接显示 `Permission denied by system`，并误用候选人的恢复文案。 | 权限拒绝、设备缺失、设备占用使用中文恢复提示；试聊使用对应的开始、恢复和结束名称。 |

同时补上结束期间禁止重新连接、迟到的麦克风/票据和 WebSocket 回调隔离；试聊按自身冻结的 `test_mode` 启动，避免依赖配置接口的加载顺序。

## Prompt 是否使用最新内容

接口、数据库快照和真实模型均已检查：已保存内容要求“蓝鲸计划”，编辑框未保存内容改为“银杏计划”，新试聊快照包含后者，实际模型输出为“欢迎参加银杏计划面试。请介绍一次数据库性能优化的经历。”。本次未复现试聊读取旧 Prompt。

回归测试验证：同一创建命令重试返回同一会话；新的试聊使用新的编辑内容与独立历史；原草稿、发布版本、正式面试列表不受试聊影响；过期版本和不存在的岗位被拒绝；重复结束不产生多条结束事件或试聊评估。
